# 学术资源匹配功能 — 远程服务器部署方案

> **文档对象**：后端运维管理人员
> **部署工具**：FileZilla 3.69.6（文件传输）+ FinalShell（SSH 终端）
> **功能代码状态**：已完成开发并通过本地自动化测试（8/8 通过）
> **适用范围**：论坛项目 `forum_project/`（Flask + SQLite3 单文件架构）

---

## 一、功能概述

在现有论坛系统上新增 **学术资源匹配** 模块：

- 用户输入研究方向关键词，系统调用 **智慧芽（PatSnap）MCP 服务** 检索全球专利 + 科技文献
- 支持结合用户资料页的"学习意向"进行匹配
- 用户可自配 **OpenAI 兼容格式的大模型 API**（DeepSeek / 通义千问 / Kimi / GLM 等），对检索结果生成摘要与匹配度分析
- 检索记录自动保存，支持历史查看

### 新增页面

| 页面 | 路由 | 说明 |
|------|------|------|
| 学术匹配入口 | `/match` | 输入关键词，选择是否结合学习意向/使用LLM |
| 匹配结果 | `/match/result/<id>` | 展示专利/文献列表 + AI 分析报告 |
| 检索历史 | `/match/history` | 历史检索记录 |
| LLM API 设置 | `/settings/llm` | 用户配置自己的大模型 API（base_url/api_key/model） |

导航栏已新增"学术匹配"入口（登录后可见）。

## 二、前置条件（管理员需准备）

| 序号 | 事项 | 说明 |
|------|------|------|
| 1 | **智慧芽专利 MCP Key** | 登录智慧芽开放平台（open.zhihuiya.com）→ API Keys 页面创建，格式 `sk-xxxxxxxx`，妥善保管 |
| 2 | **（可选）智慧芽文献 MCP 服务** | 文献检索是**独立 MCP 服务器**（区别于专利库 1458a4 服务）。需在 [marketplace/mcp-servers](https://open.zhihuiya.com/marketplace/mcp-servers) 选择并**开通文献类 MCP 服务**后，用其「生成 MCP 链接」拿到独立的 URL 与 Key；未开通则只匹配专利 |
| 3 | **远程服务器登录信息** | FinalShell 会话：服务器 IP、SSH 端口、用户名、密码/密钥 |
| 4 | **服务器 Python 环境** | Python ≥ 3.8，建议 3.10+；若尚未安装请先安装 |
| 5 | **服务器能访问外网** | 需要访问智慧芽 `connect.zhihuiya.com` 与用户配置的 LLM API 域名 |

> 说明：智慧芽 MCP 服务为付费企业服务，Key 由管理员统一配置，**不向普通用户开放**。普通用户只需自配 LLM API Key（免费/自费均可）。

## 四、服务器端配置（FinalShell）

### 4.1 连接服务器

1. 打开 FinalShell → 新建连接 → SSH → 填写服务器 IP/端口/用户名/密码
2. 连接成功后执行以下命令（`<项目目录>` 替换为实际路径，例如 `/www/forum`）

### 4.2 安装 Python 依赖

```bash
cd <项目目录>
# 升级 pip（如提示权限问题加 --user）
python3 -m pip install --upgrade pip
# 安装依赖（flask + requests）
python3 -m pip install -r requirements.txt
```

验证依赖：
```bash
python3 -c "import flask, requests; print('flask', flask.__version__); print('requests', requests.__version__)"
```

### 4.3 配置智慧芽 MCP Key

**方式 A：编辑 config.json（推荐）**

```bash
cd <项目目录>
vim config.json
```

填入（完整格式，含可选的文献服务）：
```json
{
  "patsnap": {
    "mcp_url": "https://connect.zhihuiya.com/1458a4/mcp",
    "api_key": "sk-你的专利MCPKey"
  },
  "patsnap_literature": {
    "mcp_url": "https://connect.zhihuiya.com/xxxxx/mcp",
    "api_key": "sk-你的文献MCPKey"
  },
  "_说明": "api_key 必须 sk- 开头。patsnap_literature 为独立文献服务，未开通文献服务则留空，系统会提示"
}
```

> **关于文献服务（patsnap_literature）**：智慧芽专利库（1458a4）只提供专利工具。文献检索是 marketplace 上的**另一个独立 MCP 服务器**，需先到 [open.zhihuiya.com/marketplace/mcp-servers](https://open.zhihuiya.com/marketplace/mcp-servers) 开通文献类服务，点该服务的「生成 MCP 链接」拿到**它自己的 URL**，填入上面的 `patsnap_literature.mcp_url`。**Key 可留空——智慧芽一个账户的 Key 可连接所有 MCP 服务器，会自动复用专利 Key**（若账号不同可单独填）。未配置时系统自动跳过文献匹配并给出提示。

**方式 B：环境变量（优先级高于 config.json）**

```bash
# 在服务启动脚本或 .bashrc 中追加
export PAT_SNAP_MCP_URL="https://connect.zhihuiya.com/1458a4/mcp"
export PAT_SNAP_MCP_KEY="sk-你的专利MCPKey"
export PAT_SNAP_LITERATURE_MCP_URL="https://connect.zhihuiya.com/xxxxx/mcp"   # 可选
export PAT_SNAP_LITERATURE_MCP_KEY="sk-你的文献MCPKey"                          # 可选
```

> ⚠️ 系统仅接受 `sk-` 开头的 Key。占位文本或错误 Key 会被自动忽略并提示"尚未配置"。

### 4.4 验证智慧芽 MCP 连通性（可选，直接调官方接口测试）

```bash
curl https://connect.zhihuiya.com/1458a4/mcp \
  -H "Authorization: Bearer sk-你的真实MCPKey" \
  -H "accept: application/json, text/event-stream" \
  -H "Content-Type: application/json" \
  -H "mcp-protocol-version: 2025-11-25" \
  --data-raw '{"method":"tools/list","params":{},"jsonrpc":"2.0","id":1}'
```
返回 `"tools": [...]` 即连通正常。

### 4.5 重启论坛服务

先确认当前服务的启动方式（二选一）：

```bash
# 方式一：systemd 服务（推荐生产）
sudo systemctl restart 论坛服务名        # 例如 forum.service

# 方式二：nohup 后台运行（开发/临时）
pkill -f "python.*app.py" ; sleep 1
cd <项目目录> && nohup python3 app.py > forum.log 2>&1 &

# 查看日志确认启动成功
tail -f <项目目录>/forum.log
```

> ⚠️ 首次重启时程序会自动创建新表 `user_llm_config`、`academic_search`，无需手动建表。原有论坛数据（用户/帖子/评论）不受影响。

## 六、数据库变更说明

程序启动时自动执行（幂等，重复执行安全）：

```sql
-- 新增表：用户 LLM 配置（每用户一行）
CREATE TABLE IF NOT EXISTS user_llm_config (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL UNIQUE,
    base_url    TEXT    NOT NULL DEFAULT '',
    api_key     TEXT    NOT NULL DEFAULT '',
    model       TEXT    NOT NULL DEFAULT '',
    create_time TEXT    NOT NULL,
    update_time TEXT    NOT NULL,
    FOREIGN KEY (user_id) REFERENCES user(id)
);

-- 新增表：学术匹配检索记录
CREATE TABLE IF NOT EXISTS academic_search (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL,
    keyword      TEXT    NOT NULL,
    result_count INTEGER NOT NULL DEFAULT 0,
    summary      TEXT    NOT NULL DEFAULT '',
    results_json TEXT    NOT NULL DEFAULT '',
    create_time  TEXT    NOT NULL,
    FOREIGN KEY (user_id) REFERENCES user(id)
);
```

## 七、常见问题排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 检索提示"尚未配置智慧芽MCP服务" | config.json 未填 Key / Key 非 sk- 开头 / 环境变量未生效 | 检查 config.json；重启服务使环境变量生效 |
| 检索报"Unknown tool: 'patent_search'" | tools/list 被限流/失败，代码回退默认工具名，但服务器真实工具叫 `search_patents` | 已内置候选工具名自动尝试（search_patents → patent_search → ...），并缓存 tools/list 结果 1 小时避免限流 |
| 提示"未配置文献MCP服务" | 未开通智慧芽文献服务，或 `patsnap_literature` 节点未填 | 在 marketplace 开通文献 MCP 服务后，把其 URL/Key 填入 `patsnap_literature` |
| 专利显示但缺摘要/申请人/日期 | 智慧芽字段名为 camelCase 或中文 | 已内置"精确键+关键词模糊匹配"，兼容 title/patentTitle/标题 等 |
| 检索报"智慧芽MCP网络请求失败" | 服务器无法访问外网 / MCP URL 错误 | `curl -v` 测试连通性；检查防火墙/代理 |
| 检索报"智慧芽MCP错误: 401/403" | Key 无效或权限不足 | 在智慧芽开放平台检查 Key 状态与套餐权限 |
| 检索报"429" | 触发智慧芽频率限制 | 降低使用频率或升级套餐（tools/list 已缓存，正常不会频繁触发） |
| LLM 测试连接报"401" | 用户填写的 API Key 错误/过期 | 提示用户在 `/settings/llm` 重新配置 |
| LLM 测试连接报"超时" | LLM 服务商域名不可达 / 用户填错 base_url | 确认 base_url 以 `/v1` 结尾（部分服务商不同） |
| 启动报 ImportError | 未安装 requests / 依赖不完整 | 重新执行 `pip install -r requirements.txt` |
| 结果页无专利/文献 | 关键词过宽泛/过具体，或 MCP 套餐无对应数据 | 更换关键词重试；确认智慧芽套餐包含对应数据 |

## 八、安全与合规说明

1. **智慧芽 MCP Key**：属企业付费凭证，仅存于服务器 `config.json` / 环境变量，**严禁**写入代码仓库或前端页面；如泄露请在智慧芽控制台立即吊销重建。
2. **用户 LLM API Key**：仅保存在本服务器数据库 `user_llm_config` 表中，前端以密码框展示，提交后不回显明文（Jinja2 自动转义防 XSS）；Key 仅用于向用户自选的服务商发起请求。
3. **请求超时限制**：MCP 调用超时 60s、LLM 调用超时 120s，避免第三方接口异常拖垮论坛主流程。
4. **降级策略**：智慧芽未配置或不可用时，论坛其他功能（发帖/评论/资料）完全不受影响；LLM 未配置时，检索功能正常但跳过 AI 分析。
5. **数据记录**：检索记录仅保存关键词、结果数量、摘要与结果快照，用于历史查看，不包含用户 LLM Key。
