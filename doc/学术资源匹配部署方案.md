# 学术资源匹配功能 — 部署说明（OpenAlex 文献检索 + 用户自配 LLM）

> **文档对象**：后端运维管理人员
> **功能代码状态**：已上线（前后端分离 + Docker 三容器架构）
> **适用范围**：论坛项目 `forum_project/`（Flask REST API + React 前端 + PostgreSQL）

---

## 一、功能概述

在论坛系统上提供 **学术匹配** 模块：

- 用户输入研究方向关键词，系统通过 **OpenAlex 免费 API**（`api.openalex.org/works`）检索科技文献（论文），**无需 Key、无需企业认证**
- 可选结合用户资料页的"学习意向"进行匹配
- 用户可自配 **OpenAI 兼容格式的大模型 API**（DeepSeek / 通义千问 / Kimi / GLM 等），对检索结果生成摘要与匹配度分析
- 检索记录自动保存（`academic_search` 表），支持历史查看

> 说明：此前尝试过智慧芽 MCP / USPTO PatentsView / Espacenet OPS 等专利源，均已因配额、认证或注册门槛放弃；**当前只保留论文（文献）检索**，无专利功能。

### 前端页面

| 页面 | 路由 | 说明 |
|------|------|------|
| 学术匹配入口 | `/match` | 输入关键词，展示文献源就绪状态（OpenAlex）与 LLM 配置状态 |
| 匹配结果 | `/match/result/:id` | 文献列表 + 可选 AI 分析报告 |
| 检索历史 | `/match/history` | 历史检索记录 |
| LLM API 设置 | `/settings/llm` | 用户配置自己的大模型 API（base_url / api_key / model） |

导航栏已新增"学术匹配"入口（登录后可见）。

## 二、前置条件

| 序号 | 事项 | 说明 |
|------|------|------|
| 1 | 服务器能访问外网 | 需要访问 `api.openalex.org`（文献检索）与用户配置的 LLM API 域名 |
| 2 | **无需任何文献 API Key** | OpenAlex 免费开放，`config.json` 无需配置（仅保留说明文案） |
| 3 | LLM（可选） | 用户自行在页面「LLM 设置」填写 base_url / api_key / model |

> OpenAlex 检索请求带 `mailto` 礼貌标识，可提高限流额度；无需注册。

## 三、代码与部署

### 3.1 相关文件

| 文件 | 说明 |
|------|------|
| `forum_project/academic_match.py` | 核心模块：`search_openalex`（OpenAlex 文献检索）、`llm_chat` / `analyze_matches`（OpenAI 兼容 LLM）、`save_search`（检索历史入库） |
| `forum_project/app.py` | 匹配接口：`/api/match`（状态）、`/api/match/search`（检索）、`/api/match/result/<id>`、`/api/match/history`、`/api/settings/llm`（CRUD+测试） |
| `forum_project/config.json` | 运行时配置（当前仅 `_说明`，无密钥） |
| 前端 | `frontend/src/pages/Match.jsx`、`MatchResult.jsx`、`MatchHistory.jsx`、`LlmSettings.jsx` |

### 3.2 部署方式（Docker 三容器）

后端改动走「增量更新」流程（详见 [`远程服务更新手册.md`](./远程服务更新手册.md)）：

```powershell
# 本地：构建后端镜像 → 导出
docker compose build backend
docker save forum_project-backend:latest -o backend.tar
# 上传服务器后
docker load -i backend.tar
docker compose up -d --force-recreate backend
```

涉及 `app.py` / `academic_match.py` / `config.json` 任一变更时按上述流程重建 backend 容器即可；`init_db()` 自动建表/迁移，无需手动执行 SQL。

## 四、数据库说明

程序启动时自动建表（幂等）：

- `academic_search`：检索记录（user_id / keyword / result_count / summary / results_json / create_time）
- `user_llm_config`：用户 LLM 配置（每用户一行：base_url / api_key / model）

详见 [`database_design.md`](./database_design.md) 3.5 / 3.6 节。

## 六、常见问题排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 检索提示"OpenAlex 文献检索失败" | 服务器无法访问外网 / `api.openalex.org` 超时 | `curl https://api.openalex.org/works?search=test` 测试连通性；检查防火墙/代理 |
| 结果为空 | 关键词过宽泛/过具体 | 更换关键词重试 |
| LLM 测试连接报"401" | 用户填写的 API Key 错误/过期 | 提示用户在 `/settings/llm` 重新配置 |
| LLM 测试连接报"429" | 触发服务商频率限制 | 稍后再试 |
| LLM 测试连接报"超时" | 服务商域名不可达 / base_url 填错 | 确认 base_url 以 `/v1` 结尾（部分服务商不同） |

## 七、安全与合规说明

1. **无第三方付费凭证**：文献检索走 OpenAlex 免费源，无需配置任何 Key，`config.json` 不含敏感信息。
2. **用户 LLM API Key**：仅保存在服务器数据库 `user_llm_config` 表，前端以密码框展示、提交后不回显明文。
3. **请求超时限制**：OpenAlex 检索超时 30s、LLM 调用超时 120s，避免第三方接口异常拖垮论坛主流程。
4. **降级策略**：OpenAlex 不可用时论坛其他功能不受影响；LLM 未配置时，检索功能正常但跳过 AI 分析。
5. **数据记录**：检索记录仅保存关键词、结果数量、摘要与结果快照，不包含用户 LLM Key。
