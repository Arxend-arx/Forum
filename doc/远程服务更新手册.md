## 1. 更新总流程（一次完整更新）

```
┌──────────┐   ┌──────────────┐   ┌───────────────┐   ┌─────────────┐   ┌────────────┐
│ 本地改代码 │ → │ 本地构建+测试 │ → │ 导出镜像 tar   │ → │ 上传服务器    │ → │ load + 重建 │ → 验证
│ (git)     │   │ (npm/build)  │   │ (docker save) │   │ (scp/sftp)  │   │ (compose)  │
└──────────┘   └──────────────┘   └───────────────┘   └─────────────┘   └────────────┘
```

**通用原则**
1. 先备份数据，再动容器（数据库、uploads 都要有兜底）
2. 只重建「本次改动的那个容器」，其他容器保持不动
3. 每步执行完立即验证，失败就回滚，不要带着错误往下走

## 2. 更新前端（本次 markdown 修复即此类）

前端改动只影响界面显示，不动数据，**无需备份**。

### 步骤 1：本地构建

在 `d:\工作目录\git\Forum_test\forum_project\frontend` 下：

```powershell
npm run build
```

产物在 `frontend/dist/`。

### 步骤 2：本地打镜像

两种方式任选：

**方式 A（推荐，快）**——本地已有 dist 产物，跳过 node 构建阶段：
用临时单阶段 Dockerfile `docker/frontend/Dockerfile.fast`：

```powershell
# 先复制 dist 到 build_tmp（.dockerignore 排除了 frontend/dist）
New-Item -ItemType Directory -Force -Path build_tmp | Out-Null
Copy-Item -Recurse -Force frontend/dist build_tmp/dist

docker build -f docker/frontend/Dockerfile.fast -t forum_project-frontend:latest .
```

**方式 B（标准）**——从源码完整构建（需要能拉到 node:20-alpine 基础镜像）：

```powershell
docker compose build frontend
```

> 注意：本机 Docker 拉取 registry 镜像可能因网络超时失败，失败就重试或用方式 A。

### 步骤 3：导出镜像

```powershell
docker save forum_project-frontend:latest -o frontend.tar
```

产物 `frontend.tar`（约 26MB）。

### 步骤 4：上传服务器

```powershell
# Windows 有 OpenSSH 时可直接：
scp -P 10022 frontend.tar test01@183.239.177.123:/home/test01/academy/
```

没有 scp 时用 paramiko 脚本（见文末「附录：paramiko 传输脚本」）。

### 步骤 5：服务器 load + 重建

登录服务器（`ssh -p 10022 test01@183.239.177.123`）：

```bash
cd ~/academy
docker load -i frontend.tar
docker compose up -d --force-recreate frontend
```

### 步骤 6：验证

```bash
docker ps --format '{{.Names}} {{.Status}}'        # frontend 应 Up
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:5000/   # 200
```

浏览器打开 `http://183.239.177.123:15000` 冒烟：登录、发帖（验证 markdown）、评论、私信。

### 快捷方式：纯前端改动走「dist 增量更新」（推荐）

前端只有 JS/CSS 变化时，无需传整个镜像（本机→机房带宽只有几 KB/s，传 26MB 要半小时）。**只传构建产物 dist（约 500KB）**，在服务器上基于旧前端镜像增量覆盖构建：

```powershell
# 本地
cd forum_project/frontend && npm run build
cd .. && tar -czf dist.tar.gz -C frontend dist
```

上传 `dist.tar.gz` 到服务器 `/tmp/`，然后服务器执行：

```bash
cd /tmp && mkdir -p frontend_build && tar xzf dist.tar.gz -C frontend_build
cat > frontend_build/Dockerfile.dist <<'EOF'
FROM forum_project-frontend:latest
COPY dist /usr/share/nginx/html
EOF
cd frontend_build && docker build -t forum_project-frontend:new -f Dockerfile.dist .
docker tag forum_project-frontend:new forum_project-frontend:latest
cd /home/test01/academy && docker compose up -d --force-recreate frontend
```

> 注意：构建上下文里不能有 `pgdata`（权限受限会导致 build 失败），所以构建必须在 `/tmp` 等独立目录进行。
> 已封装脚本：`deploy_tmp/step3_incremental.py`（上传 + 构建 + 重建 + 验证一键执行）。

## 4. 更新数据库容器

数据库容器一般**不需要更新**（postgres 镜像固定）。只有以下情况才动：

- 需要升级 PostgreSQL 版本（大工程，需 pg_dump 全量导出导入，单独评估）
- 容器配置/参数调整（改 compose 后 `docker compose up -d` 重建）

**日常表结构变更**不重建容器，直接执行迁移 SQL（或用后端的 `init_db()` 自动迁移——本项目后端启动时会对已有表 `ADD COLUMN IF NOT EXISTS`，改完后端代码部署即可）。

## 5. 数据备份与恢复

### 备份数据库（任何后端/DB 变更前都建议做）

```bash
# 服务器上
docker exec academy-db pg_dump -U academy -d academy -Fc > ~/academy/backup_$(date +%Y%m%d_%H%M).dump
```

### 备份上传图片

```bash
tar czf ~/academy/uploads_$(date +%Y%m%d_%H%M).tar.gz -C ~/academy uploads
```

### 恢复数据库

```bash
docker exec -i academy-db psql -U academy -d academy < backup.dump
```

### 回滚（更新失败时）

1. 旧镜像 tar 保留在服务器或本地，`docker load -i 旧镜像.tar` 后 `docker compose up -d --force-recreate <服务名>`
2. 数据库用上面的备份 dump 还原

## 7. 注意事项与常见坑

| 坑 | 说明 | 对策 |
| --- | --- | --- |
| SELinux 重启恢复 Enforcing | 容器写卷会 EPERM | 建议管理员把 `/etc/selinux/config` 改为 `permissive`（重启后仍生效） |
| `seccomp=unconfined` 被删 | 老内核 + 默认 seccomp 拦进程写文件，容器起不来 | compose 里必须保留，勿动 |
| 服务器 `docker pull` 拉不动 | 无稳定外网 | 一律本地 save → 上传 → load |
| 本机构建拉基础镜像超时 | registry 网络抖动 | 重试，或用 Dockerfile.fast 单阶段构建 |
| 动端口映射 | 机房只放行 10022/15000 | frontend 必须保持 `5000:80` |
| 老版本目录 `/home/test01/forum_project` | 已停用、占用 5000 的进程已 kill | 不要动，别启动它 |
| 镜像 tag 覆盖 | 每次 `:latest` 会覆盖 | 更新前先 `docker images` 记录旧镜像 ID，或 save 旧镜像留底 |

## 附录：paramiko 传输脚本（本机无 scp 时用）

`deploy_tmp/` 下已有机型，参考步骤：

```python
import paramiko
cli = paramiko.SSHClient()
cli.set_missing_host_key_policy(paramiko.AutoAddPolicy())
cli.connect("183.239.177.123", port=10022, username="test01", password="******", timeout=20)
sftp = cli.open_sftp()
sftp.put(r"d:\工作目录\git\Forum_test\forum_project\frontend.tar",
         "/home/test01/academy/frontend.tar")
sftp.close()
# 执行远程命令
stdin, stdout, stderr = cli.exec_command("cd ~/academy && docker load -i frontend.tar && docker compose up -d --force-recreate frontend")
print(stdout.read().decode(), stderr.read().decode())
cli.close()
```
